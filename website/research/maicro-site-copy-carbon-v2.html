mAIcro: a local backend toolbox and learning sandbox for you and your AI agents

mAIcro bundles PostgreSQL 18, generated GraphQL, vector search, graph queries, workflows and an MCP server into a single Docker container you run on your own computer. It is both a practical prototyping backend and a hands-on educational environment, shipping with guided courses inside an isolated learning instance called mAIcroverse. Built by one developer in Perth and currently in alpha, it is free to download and run locally—giving you a calm, inspectable place to learn how modern software and AI tools fit together, one small experiment at a time.

Who this is for

  • Curious builders and tinkerers working with AI agents. You already use an MCP-compatible AI client and want a real local database, API and tool layer to point it at—where you decide what the agent can reach and review what it changes.
  • Educators, students and self-taught learners. You want to look under the bonnet and understand how tables, GraphQL APIs, embeddings, graphs and workflows actually connect, using a disposable sandbox you can safely break and reset.
  • People making smaller, personal software. Not every idea needs to become a company. Sometimes you just want to replace a tangled spreadsheet, organise client notes, or build a working prototype you can show colleagues to spark better questions.
  • Teams testing sensitive workflow shapes early. You want to explore an intake form or client-record structure on a machine you control, using fictional sample data, long before you commit to a cloud vendor.

Who this isn't for

  • If you want a finished web app without opening a terminal. mAIcro is a backend and local IDE, not a chat-to-app frontend generator. You will use Docker, a terminal and GraphQL, and connect your own frontend when you want a custom interface.
  • If you need hosted sign-in, managed compliance and a production path today. mAIcro is early alpha software without built-in end-user authentication tiers, SLAs or hosted infrastructure. Pick a mature hosted backend platform for live customer data.
  • If your main job is syncing dozens of cloud SaaS apps. When your workflow is mostly moving events between third-party cloud tools rather than storing and querying your own data, a dedicated cloud automation tool will save you time.
  • If you want the tiniest possible backend with zero containers. If all you need is a single-file database with user accounts and no vectors, graphs or Docker, a lightweight single-binary backend is a simpler fit.

What mAIcro is (and why it's built this way)

  1. One container instead of five separate services.
    - What it is: A single public Docker image (bloxez/maicro-g2a) running on your machine, storing data in a local folder (~/maicro-data by default).
    - Why it matters: Standing up a database, a vector store, a graph engine, a job scheduler and an API server usually eats the first week of a prototype. Putting them in one container means one install, no idle cloud projects pausing mid-experiment, and one place to look when something breaks.

  2. A toolbox for you and your agents—not a black box.
    - What it is: Standard, inspectable technologies connected cleanly, rather than hidden behind proprietary no-code blocks.
    - Why it matters: AI agents can draft code in seconds, yet they still need structured places to store records, check types and run repeatable steps. When you can read the tables, types and queries yourself, you can verify what the agent did and learn as you go.

  3. A tool for building, paired with a place for learning.
    - What it is: Alongside your own projects, you can spin up mAIcroverse—a separate learning instance pre-loaded with 15 practical courses and sample files.
    - Why it matters: Learning by doing is easier when mistakes don't touch your real work. Each course states clearly what you will build and what its setup script resets, so you can experiment freely and start fresh whenever you like.

How the pieces fit together

Think of mAIcro as a step-by-step stack. You can start at step 1 with a single table, and only reach for the later steps when your problem genuinely asks for them.

1. PostgreSQL 18 → Generated GraphQL

  • What it is: You define relational tables in PostgreSQL 18 and reload the schema. mAIcro automatically generates the matching GraphQL types, queries and mutations. You can also query CSV and JSONL files in File Storage directly as GraphQL results.
  • Why you'd care: GraphQL gives both you and your AI tools an explicit, typed contract for reading and changing data—no boilerplate CRUD endpoints to write by hand.
  • In the courses: In Clients and Documents, you create and seed a clients table, reload the schema, and query client records alongside linked documents. In Data File Fetch and Data Import, you read raw customer and order files and turn them into queryable tables.

2. Vectors and similarity search (pgvector)

  • What it is: Document-processing tools and pgvector live right inside the same PostgreSQL database, letting you chunk text, store numerical embeddings and search by similarity alongside your regular rows.
  • Why you'd care: Exact keyword filters miss fuzzy questions like "How often should the seedlings be watered?" Vector search helps you find relevant passages before generating an answer. (And as the courses teach: similarity isn't truth—always check returned passages against the source.)
  • In the courses: Book Club combines relational tables with semantic search across notes, so you can test what retrieval catches and what it misses.

3. Graphs and relationships (Apache AGE / openCypher)

  • What it is: Apache AGE adds graph modelling to PostgreSQL. You model nodes and edges, query them using openCypher, and wrap those Cypher queries as reusable GraphQL operations.
  • Why you'd care: Some questions are really about connections—who worked where, how books and readers link, or which rules govern a relationship—where nested table joins quickly get messy.
  • In the courses: HR Graph models employees, employers and employment history in AGE, enforcing business rules through GraphQL-wrapped Cypher operations.

4. Workflows, cron jobs and typed AI tasks

  • What it is: You compose operations into multi-step workflow chains—mixing database queries, data processing, scheduled cron jobs, browser automation (Browser X4m), persistent memory blocks, and AI tasks/signatures backed by registered GraphQL output types.
  • Why you'd care: Requiring an AI step to match a registered GraphQL type turns vague text completions into predictable, structured outputs your next workflow step can trust.
  • In the courses: AI Tasks and AI Signatures and Types walk through defining explicit input/output contracts for document extraction; Scheduled Weather Collector runs a cron job to ingest weather readings; ASX Watcher combines market data, Markdown reports and browser extraction.

5. TypeScript modules and SQL / REST API wrappers

  • What it is: You can extend the platform with custom TypeScript modules, and wrap custom SQL or external REST APIs so they appear as native GraphQL operations inside your schema.
  • Why you'd care: External services become clean building blocks with mapped inputs, outputs, credentials and rate-limit awareness, rather than scattered fetch calls.
  • In the courses: API Wrappers teaches you how to map an external REST API into your GraphQL schema and test it safely.

6. MCP for your AI agents

  • What it is: With Model Context Protocol (MCP) enabled, compatible AI clients can connect to mAIcro, inspect your schema and call the GraphQL operations and workflows you've built.
  • Why you'd care: Instead of giving an agent raw shell access and hoping for the best, you give it well-defined tools over your data, APIs and processes. You stay in charge of which client connects, what it can access and how its work is reviewed.
  • In practice: Use an agent to help plan a schema, query your Memory Essentials blocks, or test small retrieval loops against sample notes.

7. The embedded IDE (and your own frontend)

  • What it is: Everything runs with a browser-based local IDE (at http://localhost:4321 by default) that includes local VitePress help, File Storage, a Markdown wiki browser, multi-step Forms, Charts/dashboards and a CLI. When you're ready, you can also connect your own frontend to the GraphQL API.
  • Why you'd care: You can see and interact with your prototype immediately—without building a custom UI first.
  • In the courses: Markdown Foundations builds a connected wiki with diagrams and media; Forms walks through a multi-step aged-care intake form with grouped demonstration submissions.

8. Courses and mAIcroverse

  • What it is: Fifteen guided, hands-on courses in the open GPL-3.0 maicroverse repository—covering Markdown, data import, graphs, vectors, memory, API wrappers, cron jobs, AI signatures, forms and browser automation.
  • Why you'd care: You don't have to stare at a blank schema wondering where to begin. Pick an everyday scenario, run it in your disposable learning instance, inspect every moving part, and adapt the pattern to your own idea.

Limits, plainly

Knowing what to expect up front makes for a much smoother first afternoon:

  • Early alpha software. mAIcro is at version 0.1.x and ships frequent updates. Expect rough edges and changes between releases; keep it for learning, personal tools and prototypes rather than live production or real client records.
  • One solo founder. mAIcro is built and maintained by Chris Nurse (BloxEZ) in Perth, Western Australia.
  • Local and self-hosted only. There is no hosted cloud version and no one-click browser sandbox. You will need Docker (roughly a 635 MB image download), a terminal, and willingness to learn a little GraphQL along the way.
  • Local hosting doesn't keep external AI calls local. Your database lives on your machine, and the learning setup configures AI models through your own OpenRouter API key. Any prompt, document chunk or API payload sent to an external model provider or REST API leaves your computer—so stick to fictional or sample data while you explore.
  • Development-grade default credentials. Out of the box, the installer uses default credentials and signing secrets, exposes local container ports, and the mAIcroverse setup resets the learning admin key to a known public string (maicrog2a) while allowing outbound fetches. Keep your instance on your own machine or lock these settings down before putting it on a shared network.
  • Course setups wipe example data. Many courses drop and recreate demo tables, graphs, cron jobs or memory blocks so you get a clean run. Always run courses inside the disposable mAIcroverse learning instance, separate from projects you care about.
  • Unpublished legals and platform source. While the maicroverse course repository is public under GPL-3.0, the core platform source code, software licence, pricing page, privacy policy and terms of service are not yet published on the site.

Get started

Set aside about 15 minutes with Docker and a terminal open.

  1. Install and start Docker.
    - On macOS (Intel or Apple Silicon) or Windows, start Docker Desktop. (On Windows, you can use PowerShell, or WSL 2 with Docker integration enabled.)
    - On Linux, start Docker Engine or Docker Desktop.

  2. Review the install script first.
    - Before running any piped installer, inspect maicro-install/run.sh (or run.ps1 for Windows) in the bloxez/maicroverse GitHub repository.
    - Note what it does: it can start Docker, request administrator privileges, create configuration and data directories (~/maicro-data by default), modify Linux Docker-group membership, and replace any existing container named maicro (on Windows, it also replaces the platform config file—back up existing data before reinstalling).

  3. Run the installer for your platform.
    - On macOS, Linux or Windows WSL 2, run in your terminal:
    sh curl -fsSL https://raw.githubusercontent.com/bloxez/maicroverse/main/maicro-install/run.sh | sh
    - On Windows PowerShell, copy the irm ... | iex PowerShell command from https://maicro.app/get-started (which runs run.ps1 from the maicroverse repository).

  4. Open your local IDE and help guide.
    - Once the maicro container is running, visit http://localhost:4321 (and http://localhost:4321/help/ide/ for setup and local documentation).
    - If the page doesn't load, check that Docker is running and inspect docker logs maicro.

  5. Optional: set up the mAIcroverse learning instance.
    - To try the 15 guided courses in an isolated, resettable sandbox, run this while your maicro container is up (review create-mv.sh first if you'd like to see every step):
    sh docker exec -it maicro bash -lc 'curl -fsSL https://raw.githubusercontent.com/bloxez/maicroverse/main/create-mv.sh | bash'
    - During setup you can enter an OpenRouter API key for AI-powered lessons. Remember that this learning instance uses a known default admin key (maicrog2a) and course scripts wipe their demo data on reset—treat it purely as your practice space, then browse https://maicro.app/courses to pick your first lesson.
