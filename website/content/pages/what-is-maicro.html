What mAIcro is (and why it's built this way)

One container instead of five separate services.

A single public Docker image (bloxez/maicro-g2a) running on your machine, storing data in a local folder (~/maicro-data by default).

Standing up a database, a vector store, a graph engine, a job scheduler and an API server usually eats the first week of a prototype. Putting them in one container means one install, no idle cloud projects pausing mid-experiment, and one place to look when something breaks.

A toolbox for you and your agents—not a black box.

Standard, inspectable technologies connected cleanly, rather than hidden behind proprietary no-code blocks.

AI agents can draft code in seconds, yet they still need structured places to store records, check types and run repeatable steps. When you can read the tables, types and queries yourself, you can verify what the agent did and learn as you go.

A tool for building, paired with a place for learning.

Alongside your own projects, you can spin up mAIcroverse—a separate learning instance pre-loaded with 15 practical courses and sample files.

Learning by doing is easier when mistakes don't touch your real work. Each course states clearly what you will build and what its setup script resets, so you can experiment freely and start fresh whenever you like.

How the pieces fit together

Think of mAIcro as a step-by-step stack. You can start at step 1 with a single table, and only reach for the later steps when your problem genuinely asks for them.

PostgreSQL 18 → Generated GraphQL

You define relational tables in PostgreSQL 18 and reload the schema. mAIcro automatically generates the matching GraphQL types, queries and mutations. You can also query CSV and JSONL files in File Storage directly as GraphQL results.

GraphQL gives both you and your AI tools an explicit, typed contract for reading and changing data—no boilerplate CRUD endpoints to write by hand.

In Clients and Documents, you create and seed a clients table, reload the schema, and query client records alongside linked documents. In Data File Fetch and Data Import, you read raw customer and order files and turn them into queryable tables.

Vectors and similarity search (pgvector)

Document-processing tools and pgvector live right inside the same PostgreSQL database, letting you chunk text, store numerical embeddings and search by similarity alongside your regular rows.

Exact keyword filters miss fuzzy questions like "How often should the seedlings be watered?" Vector search helps you find relevant passages before generating an answer.

As the courses teach: similarity isn't truth—always check returned passages against the source.

Book Club combines relational tables with semantic search across notes, so you can test what retrieval catches and what it misses.

Graphs and relationships (Apache AGE / openCypher)

Apache AGE adds graph modelling to PostgreSQL. You model nodes and edges, query them using openCypher, and wrap those Cypher queries as reusable GraphQL operations.

Some questions are really about connections—who worked where, how books and readers link, or which rules govern a relationship—where nested table joins quickly get messy.

HR Graph models employees, employers and employment history in AGE, enforcing business rules through GraphQL-wrapped Cypher operations.

Workflows, cron jobs and typed AI tasks

You compose operations into multi-step workflow chains—mixing database queries, data processing, scheduled cron jobs, browser automation (Browser X4m), persistent memory blocks, and AI tasks/signatures backed by registered GraphQL output types.

Requiring an AI step to match a registered GraphQL type turns vague text completions into predictable, structured outputs your next workflow step can trust.

AI Tasks and AI Signatures and Types walk through defining explicit input/output contracts for document extraction; Scheduled Weather Collector runs a cron job to ingest weather readings; ASX Watcher combines market data, Markdown reports and browser extraction.

TypeScript modules and SQL / REST API wrappers

You can extend the platform with custom TypeScript modules, and wrap custom SQL or external REST APIs so they appear as native GraphQL operations inside your schema.

External services become clean building blocks with mapped inputs, outputs, credentials and rate-limit awareness, rather than scattered fetch calls.

API Wrappers teaches you how to map an external REST API into your GraphQL schema and test it safely.

MCP for your AI agents

With Model Context Protocol (MCP) enabled, compatible AI clients can connect to mAIcro, inspect your schema and call the GraphQL operations and workflows you've built.

Instead of giving an agent raw shell access and hoping for the best, you give it well-defined tools over your data, APIs and processes. You stay in charge of which client connects, what it can access and how its work is reviewed.

Use an agent to help plan a schema, query your Memory Essentials blocks, or test small retrieval loops against sample notes.

The embedded IDE (and your own frontend)

Everything runs with a browser-based local IDE (at http://localhost:4321 by default) that includes local VitePress help, File Storage, a Markdown wiki browser, multi-step Forms, Charts/dashboards and a CLI. When you're ready, you can also connect your own frontend to the GraphQL API.

You can see and interact with your prototype immediately—without building a custom UI first.

Markdown Foundations builds a connected wiki with diagrams and media; Forms walks through a multi-step aged-care intake form with grouped demonstration submissions.

Courses and mAIcroverse

Fifteen guided, hands-on courses in the open GPL-3.0 maicroverse repository—covering Markdown, data import, graphs, vectors, memory, API wrappers, cron jobs, AI signatures, forms and browser automation.

You don't have to stare at a blank schema wondering where to begin. Pick an everyday scenario, run it in your disposable learning instance, inspect every moving part, and adapt the pattern to your own idea.
